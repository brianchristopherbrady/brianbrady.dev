Local-first mapping / accessibility observations / development project

blipmap

A street-level accessibility notebook for recording pedestrian conditions, reviewing nearby barriers, and planning non-driving trips. Its central record is a Patch: a location with category, severity, status, notes, and an optional local photo.

The interface separates observations from promises. A recorded curb ramp, a nearby barrier, and a provider-generated route each carry different evidence. Missing observations must never become an implied guarantee of access.

View repo View demo

From street to record

Guest users can add and edit patches, browse by category and severity, undo a deletion, and import or export validated GeoJSON. Records and local photos stay in IndexedDB, making the observation workflow independent of account creation.

A small Seattle baseline supplies source-derived observations. Exact original-report links provide context without copying third-party street imagery or treating the nearest image as evidence.

A path is not a guarantee

Path Check finds recorded observations within 15 meters of a drawn path. Trip planning requests walking, wheelchair, hiking, or cycling directions through OpenRouteService.

Mobility aids and access requirements are separate settings. Unsupported routing requirements block generation with an explanation instead of silently relaxing the user's constraints.

Storage boundaries

Optional Supabase accounts save explicitly submitted private preferences and favorite destinations. Signing in does not upload patches or make browser-local records private to that account.

Local-first is not fully offline: map tiles, search, routing, source refreshes, and account operations still depend on external services.

Current limits

This is a development project, not live GPS navigation or an emergency service. Observation age, limited source coverage, and incomplete provider data matter. Critical access needs require independent confirmation.

The current public Nominatim autocomplete integration needs a provider-compliant replacement or revised interaction before public deployment.
