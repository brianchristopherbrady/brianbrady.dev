How I work

I care about the space between design intent and production code.

Most of my work sits between design and engineering. I care about the part where a visual idea becomes a reusable component, a product workflow, a documentation page, a testable behavior, or a tool that helps someone else make the next good decision faster.

Recently, I have been especially interested in AI-assisted development: not as a replacement for taste or craft, but as a way to make design review, code navigation, implementation planning, and quality checks more consistent.

Design systems

I build and improve reusable UI with attention to states, examples, accessibility, documentation, and adoption.

Frontend architecture

I like practical structure: code that is understandable, reusable, easy to validate, and shaped around product needs.

AI workflows

I design agent workflows that use repository context, design constraints, and review discipline instead of guessing.

Product judgment

I care about the user-facing result: the interface should be clear, resilient, and worth coming back to.
